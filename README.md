# Трекер продаж авторазбора

Веб-приложение для быстрого текстового ввода продаж и возвратов автозапчастей, статистики и выгрузки в Excel.
Интерфейс на русском, часовой пояс Asia/Almaty, суммы — целые тенге.

- **Backend:** FastAPI, SQLAlchemy 2, Alembic, psycopg 3, openpyxl, pytest — папка `backend/`, деплой на Render.
- **Frontend:** React + Vite + TypeScript — папка `frontend/`, деплой на Vercel.
- **БД:** PostgreSQL в Supabase (только как база: без Supabase Auth/Realtime/клиентского доступа).

## Формат ввода

```
мерс210 сафа левый правый - 25000
к20 капот с обшивкой - 70 000
С ТКЕ щиток прибора - 35000            ← старый завоз: «с <код машины> <запчасть> - <цена>»
возврат к20 капот с обшивкой - 70000
возврат С ТКЕ щиток прибора - 35000
```

Разделитель цены — ` - `, ` – ` или ` — ` (с пробелами); строка делится по последнему разделителю,
поэтому дефис в названии запчасти допустим. Марки не создаются автоматически — только на странице «Марки».

## Локальный запуск

Нужны Python 3.12+, Node 20+ и PostgreSQL (локальный или Docker).

```bash
# PostgreSQL в Docker (если не установлен локально)
docker run -d --name report-pg -e POSTGRES_PASSWORD=postgres -p 5432:5432 postgres:18
```

1. Скопируйте `.env.example` в `.env` (в корне проекта) и заполните. Для локальной базы:
   `DATABASE_URL=postgresql+psycopg://postgres:postgres@localhost:5432/report_app`, `COOKIE_SECURE=false`.
   Саму базу `report_app` создайте заранее (`createdb report_app` или через pgAdmin).
2. Backend:
   ```bash
   cd backend
   python -m venv .venv
   .venv\Scripts\activate          # Linux/macOS: source .venv/bin/activate
   pip install -r requirements.txt
   alembic upgrade head
   uvicorn app.main:app --reload --port 8000
   ```
3. Frontend (в другом терминале):
   ```bash
   cd frontend
   npm install
   npm run dev
   ```
4. Откройте http://localhost:5173 и войдите с паролем из `APP_PASSWORD`.
   Vite проксирует `/api` и `/health` на `http://localhost:8000` (адрес меняется переменной `BACKEND_URL`).

## Тесты

```bash
cd backend
.venv\Scripts\python -m pytest
```

Тесты работают на отдельной базе из `TEST_DATABASE_URL`
(по умолчанию `postgresql+psycopg://postgres:postgres@localhost:5432/report_app_test`).
База создаётся автоматически, схема накатывается миграциями Alembic, перед каждым тестом таблицы очищаются.
`DATABASE_URL` из `.env` в тестах намеренно игнорируется, чтобы не задеть рабочую базу.
Если PostgreSQL недоступен, тесты с БД пропускаются (тесты парсера выполняются всегда).

## Миграции

```bash
cd backend
alembic upgrade head                              # применить
alembic revision --autogenerate -m "описание"     # новая миграция после изменения app/models.py
```

Первая миграция создаёт таблицы `cars`, `sales`, `returns` и стартовые марки `к10`, `к20`, `к25`, `мерс210`, `пб5+`, `с`.
На Render миграции выполняются при каждом старте (`startCommand` в `render.yaml`).

## Деплой

### 1. Supabase (БД)
1. Создайте проект. Project Settings → Database → **Connection string → Session pooler**.
2. Скопируйте строку (`postgresql://postgres.<ref>:<password>@aws-0-<region>.pooler.supabase.com:5432/postgres`) — это `DATABASE_URL`.

Почему Session pooler: прямое подключение Supabase работает только по IPv6, а Render — по IPv4.
Transaction pooler (порт 6543) тоже возможен, но ломает prepared statements psycopg 3 — Session проще.

### 2. Render (backend)
1. New → Blueprint → выберите репозиторий: Render прочитает `render.yaml`
   (или вручную: Web Service, Root Directory `backend`, команды из `render.yaml`).
2. Задайте `DATABASE_URL` и `APP_PASSWORD`. `JWT_SECRET` сгенерируется сам, `COOKIE_SECURE=true` уже задан.
3. После деплоя проверьте `https://<сервис>.onrender.com/health` → `{"status":"ok"}`.

Бесплатный инстанс Render засыпает после ~15 минут без запросов; первый запрос после этого идёт 30–60 секунд.
Интерфейс в это время показывает «Сервер просыпается…». Чтобы не засыпал, можно пинговать `/health` чаще (например, раз в 10 минут).

### 3. Vercel (frontend)
1. В `frontend/vercel.json` указан адрес сервиса Render (`autoparts-sales-tracker.onrender.com`); при смене сервиса поменяйте его.
2. New Project → репозиторий, **Root Directory: `frontend`**, Framework: Vite (Build `npm run build`, Output `dist`).

Vercel проксирует `/api/*` на Render, поэтому для браузера фронт и API на одном домене:
cookie авторизации первичная (`SameSite=Lax`, `Secure`), CORS не нужен. Без прокси Safari на iPhone
блокировал бы стороннюю cookie и вход бы не работал.

### 4. Cron для Supabase
Внешний cron (например, cron-job.org) раз в три дня вызывает `GET https://<сервис>.onrender.com/health` —
напрямую в Render, не через Vercel. Эндпоинт выполняет `SELECT 1`, чтобы Supabase не приостанавливал проект.

## Принятые решения по неоднозначным местам

- **Дата.** Поле даты на странице ввода по умолчанию — сегодня (Алматы), можно выбрать прошлую дату; будущие даты запрещены.
  Время не вводится: продажа сохраняется как 12:00 по Алматы выбранного дня, чтобы дата не сдвигалась при пересчёте поясов.
- **Возвраты всегда проводятся сегодняшней датой** (`returned_at` = 12:00 сегодня), независимо от даты в форме;
  в предпросмотре об этом есть подсказка. `sold_at` копируется из исходной продажи.
- **«Самая новая» продажа** — наибольший `sold_at`, при равенстве — продажа, добавленная в этом же вводе, затем наибольший `id`.
- **Выбор при неоднозначном возврате** передаётся как `choices: {номер_строки: ref}`, где ref — `sale:<id>` (продажа из БД)
  или `line:<номер>` (продажа, добавленная выше в том же вводе: у неё ещё нет id). Если выбор не передан, берётся самая новая.
- **Номер строки** — номер в исходном тексте с учётом пустых строк.
- **Сравнение запчастей** при возврате — без учёта регистра и повторных пробелов. `old_car_code` — точное совпадение
  после перевода в верхний регистр (латиница в коде на кириллицу не заменяется — как в ТЗ).
- **Похожие продажи** при 0 совпадений — до 5 продаж той же марки, ранжированных по похожести названия, совпадению цены и кода.
- **Отмена возврата** восстанавливает продажу с исходным `sold_at`, но с новым `id` (в `returns` исходный id не хранится).
- **Редактирование продажи** — через форму: марка, код (только для `с`, обязателен), запчасть, цена, дата.
- **Марки:** название нормализуется так же, как при разборе (нижний регистр, латиница → кириллица), одно слово без пробелов,
  слово «возврат» запрещено. Марку `с` нельзя переименовать или удалить.
- **Статистика «неделя или месяц»** — шаг группировки: по неделям (с понедельника) или по месяцам за выбранный период.
  Без дат — последние 12 недель или 12 месяцев. Выручка — по `sales.sold_at`, возвраты — отдельно по `returns.returned_at`.
- **Excel:** период фильтрует продажи по дате продажи, возвраты — по дате возврата. Сортировка листа «Продажи»:
  марка, код старой машины, дата. Лист «Итоги» — по маркам в алфавитном порядке, «с» показывается как «Старый завоз».
- **Деплой** разделён на Render (API) и Vercel (статика) вместо одного сервиса; FastAPI фронтенд не раздаёт.
- **Вход:** не больше 10 неверных паролей за 15 минут с одного IP; есть выход (`POST /api/auth/logout`).
- pytest и httpx включены в `requirements.txt` для простоты (один файл зависимостей).

## API (кратко)

Все `/api/*` требуют входа, кроме `POST /api/auth/login`.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health` | `SELECT 1`, без авторизации |
| POST | `/api/auth/login`, `/api/auth/logout` · GET `/api/auth/me` | вход / выход / проверка |
| POST | `/api/entries/preview` | разбор пакета строк без сохранения |
| POST | `/api/entries/commit` | сохранение, каждая строка в своей транзакции |
| GET, PATCH, DELETE | `/api/sales`, `/api/sales/{id}` | список с фильтрами `from`, `to`, `car_id`, `q`; изменение; удаление |
| GET · POST | `/api/returns` · `/api/returns/{id}/cancel` | список; отмена возврата |
| GET, POST, PATCH, DELETE | `/api/cars`, `/api/cars/{id}` | марки |
| GET | `/api/stats?group=week\|month&from&to&car_id` | статистика |
| GET | `/api/export.xlsx?from&to` | выгрузка в Excel |
| GET | `/api/suggestions` | подсказки для поля ввода |
